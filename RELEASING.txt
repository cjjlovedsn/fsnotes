FSNotes 定制版：打 tag 自动发布 Mac 应用

首次使用
在 GitHub 仓库的 Actions 页面启用工作流。使用 GitHub 自带的 GITHUB_TOKEN，
无需配置个人 Token 或 Apple 开发者证书。

日常发布
先提交并推送改动，再给该提交创建一个新标签：

    git push origin master
    git tag -a custom-2026.11.16.3 -m "FSNotes custom release"
    git push origin custom-2026.11.16.3

也支持以 v 开头的版本标签，例如 v7.6.1-custom.1。
标签仅允许字母、数字、点、下划线和短横线，v/custom- 前缀后须以数字开头。
不要重复使用已发布的标签；新版本使用新标签。

GitHub Actions 自动执行
1. 从标签指定的确切提交获取源码，运行原生编辑器组件检查。
2. 在 macOS 26 Apple Silicon runner 上使用 Xcode Release 配置编译。
3. 给应用写入定制标签和源码提交信息，完成临时签名与签名校验。
4. 打包 FSNotes.app、README 和 MIT 许可证，生成 SHA256SUMS.txt。
5. 核对构建产物后上传附件，最后正式发布 GitHub Release。

构建或组件检查失败时，工作流不会发布 Release；可在失败运行的 Artifacts
中下载日志。只有上传完成后才会把草稿转为正式发布，避免出现缺少应用包的版本。
包含 -alpha、-beta 或 -rc 的标签发布为 Pre-release，其余标签设为 Latest。

重新运行
在 Actions > macOS Release > Run workflow 中填写已存在的标签即可。
标签必须包含本工作流、构建脚本和检查程序；初次手工发布的
custom-2026.11.16.1 不包含这些脚本，不能用于此入口。
已经正式发布的版本不会被自动覆盖，失败留下的草稿可重新运行以完成上传。

下载
    https://github.com/cjjlovedsn/fsnotes/releases/latest

目前生成 arm64（Apple Silicon）应用，不包含 Intel 版本；应用使用临时签名，
未经过 Apple 公证。应用内部沿用上游版本号；定制标签与提交见包内 README
及 Info.plist 的 FSNotesCustomReleaseTag、FSNotesSourceCommit 字段。

本机复现
在 macOS 上安装 Xcode 后运行：

    Tests/CodeBlockCopy/run.sh
    scripts/build-macos-release.sh custom-2026.11.16.3

输出位于 dist/，中间产物位于 .build-release/。
